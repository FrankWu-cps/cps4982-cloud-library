# Cloud Library public Django deployment

This is the actual Django application serving an immutable projection of a real PySpark 4.0.1 TF-IDF computation. PySpark and Java are used for local indexing and optional local live-Spark queries. Cloud requests use the exact exported numeric postings; the cloud does not recalculate TF-IDF in JavaScript or Python.

## Deployment bundle

Only publish a folder produced by `scripts/package_release.py`. It includes the application and its bilingual assets, the selected 146 original electronic-book texts with all embedded licenses intact, catalog, Spark manifest and Parquet parts, web-only requirements, and chunked gzip archives of the SQLite serving artifact. Every generated part is less than 40 MiB, below GitHub's 50 MiB warning threshold. The original archive, excluded large book, local virtual environment, runtime downloads, reports, credentials, and local absolute paths are not included.

The staging `release_manifest.json` records the SHA-256 and size of every included file. `scripts/deploy_restore.py` verifies each compressed part, the joined gzip, the uncompressed SQLite database, SQLite quick_check, and its document count before the server starts. Original book bytes remain unchanged.

## Render

Use an authenticated Render workspace to create a **Free Python web service** from the staged source repository, or apply `render.yaml` from that repository. No service or paid plan is created by the packaging scripts.

- Build: `bash deploy/build.sh`
- Start: `bash deploy/start.sh`
- Health: `/api/health`
- Required secret: `DJANGO_SECRET_KEY`, generated by Render and never committed.
- Render supplies `RENDER_EXTERNAL_HOSTNAME`; production ALLOWED_HOSTS is limited to that exact hostname unless explicitly overridden with a comma-separated list.
- The server runs one Gunicorn process with four threads. `ALLOW_LIVE_SPARK=0` prevents per-request JVM startup. `/api/health` reports `live_spark_available: false`.

Render's Free web service sleeps after 15 idle minutes, with approximately a one-minute cold start on the next visit. Its local filesystem is ephemeral. Here, the immutable index and books are reconstructed from the versioned deployment bundle, so no persistent disk is needed. Do not add accounts, uploads, or mutable database state without separate durable storage. A fixed public HTTPS URL is supplied by the host only after an authorized deployment succeeds; this source bundle is not itself a published website.

Official hosting documentation: https://render.com/docs/free and https://render.com/docs/deploy-django.
